# Прототипы интерфейса

Здесь лежат макеты, которые согласуются **до** переписывания рабочего кода.
На работу сайта не влияют: каталог закрыт от публикации через `.assetsignore`
и не подключается ни одной страницей.

## `crm-v2.html` — новый интерфейс диспетчерской

Что это: один самодостаточный HTML-файл с демонстрационными данными.
Открывается двойным щелчком в браузере, ничего запускать не нужно.
API не вызывается, данные вымышленные.

### Что изменено по сравнению с текущей CRM

| Сейчас (`crm-next.js`) | В макете |
|---|---|
| Одна колонка: счётчики, поиск, карточки | Три зоны: разделы, список, карточка заявки |
| Карточка заявки — строка в списке, действия внутри неё | Карточка открывается сбоку, действия собраны в одном месте |
| Статус меняется выпадающим списком | Шкала этапов: видно, где заявка и что дальше |
| ~3–4 заявки на экран | ~9–12 заявок: таблица плотнее карточек |
| Простой заявки не виден | Заявки старше 2 часов помечены ⚠, в сайдбаре сводка |
| Разделы только по статусам | Плюс справочники: автопарк, тарифы, доступы |
| На телефоне — те же карточки | Отдельная раскладка: крупные карточки + нижняя навигация |

### Цвета

Палитра взята с сайта, чтобы CRM выглядела частью продукта, а не отдельным
сервисом. Ключевые значения:

| Токен | Значение | Где используется |
|---|---|---|
| `--brand` | `#8B2536` | основные действия, активный раздел, номера заявок |
| `--brand-soft` | `#FBF2F4` | подсветка выбранной строки |
| `--st-new` | `#2866A0` | статус «Новая» |
| `--st-processing` | `#B8860B` | «В работе» |
| `--st-transit` | `#19786D` | «В рейсе» |
| `--st-completed` | `#237B50` | «Завершена» |

### Шрифты

Manrope для текста и IBM Plex Mono для чисел, номеров и служебных подписей —
как в текущей CRM. Менять не обязательно, это уже согласовано с сайтом.

## Как показать макет в Figma

Прямого экспорта в Figma нет, но есть два рабочих пути.

**Вариант 1 — плагин для импорта (быстрее).** Открыть Figma → плагины →
найти `html.to.design` или `Figma to HTML` → вставить в него содержимое
`crm-v2.html`. Плагин разберёт разметку и стили и создаст редактируемые слои.

**Вариант 2 — вставить как изображение.** Перетащить `crm-desktop.png` и
`crm-mobile.png` на холст Figma. Подойдёт, если нужен только визуальный
ориентир, без редактирования слоёв.

## Скриншоты

| Файл | Разрешение | Что показывает |
|---|---|---|
| `crm-desktop.png` | 1440×900 | основной сценарий диспетчера |

Пересобрать скриншоты после правок макета:

```bash
node _tools/shoot-prototype.mjs
```

## Что нужно решить перед реализацией

1. **Три зоны против одной.** Трёхзонная раскладка эффективнее на большом
   экране, но на 1180px карточка заявки уже не помещается — в макете она
   скрывается. Возможно, стоит сделать её выдвижной панелью поверх списка.
2. **Справочники в сайдбаре.** «Автопарк и водители», «Тарифы» — это новые
   разделы, которых сейчас нет ни в API, ни в базе. Либо убираем из макета,
   либо планируем как отдельную задачу.
3. **Поле «Диспетчер» и назначение.** Сейчас в данных есть `dispatcher`
   (кто ведёт) и `assignedTo` (исполнитель). В макете одно поле — надо
   определить, какое из них показывать.
4. **Статус «Отменена».** В схеме D1 есть `cancelled`, но в текущем интерфейсе
   он не выведен. В макете добавлен — подтвердите, что он нужен в работе.
5. **Эмодзи в кнопках действий.** В макете стоят для наглядности. Для
   продакшна лучше SVG-иконки: эмодзи по-разному рисуются в Windows,
   Android и iOS.
