# Настройка Cloudflare для ASMA Lines

Сайт размещён на **Cloudflare Pages**, весь серверный код — в `_worker.js`,
статика — в корне репозитория. Node-сервер (`server.js`) нужен только для
локальной разработки.

Документ описывает, что нужно настроить в Cloudflare **после** этих изменений.
Пока пункты 1–3 не выполнены, сайт работает в ограниченном режиме:
страницы открываются, но заявки не принимаются (см. «Режимы работы»).

---

## 0. Что изменилось и почему нужна настройка

| Было | Стало | Что требуется от вас |
|---|---|---|
| Токен бота и ключи были в коде | Читаются из секретов | Задать секреты (п. 2) |
| Заявки хранились в публичном JSON-бине | Хранятся в Cloudflare D1 | Создать БД и биндинг (п. 1) |
| Любой мог войти по `plombit` / `2026` | Только подписанный Telegram initData | Ничего, кроме настройки секретов |
| Вебхук принимал любые запросы | Проверяется секрет вебхука | Задать секрет (п. 2, 4) |
| Заявки из старого бина | Импортируются разово | Выполнить импорт (п. 3) |

## 1. База данных D1 (хранилище заявок)

Без неё Worker работает **только на чтение** и не принимает заявки.

### 1.1 Создать базу

```bash
npx wrangler login
npx wrangler d1 create asma-lines
```

Команда выведет `database_id` — он понадобится в следующем шаге.

### 1.2 Прописать биндинг

Откройте `wrangler.toml`, раскомментируйте блок и подставьте свой id:

```toml
[[d1_databases]]
binding = "DB"
database_name = "asma-lines"
database_id = "ВСТАВЬТЕ-ID-ИЗ-ВЫВОДА-wrangler-d1-create"
```

> Имя биндинга должно быть именно `DB` — Worker ищет его по этому имени.

### 1.3 Применить схему

```bash
npx wrangler d1 execute asma-lines --remote --file=./schema.sql
```

Схема создаёт таблицы `leads`, `deleted_leads`, `access_users`, `employees`,
`counters`, `meta`. Worker дополнительно создаёт их сам при первом запросе,
так что этот шаг — подстраховка.

### 1.4 Если проект подключён через Git

Cloudflare → **Workers & Pages** → ваш проект → **Settings** → **Functions** →
**D1 database bindings** → Add → Variable name: `DB`, выбрать базу `asma-lines`.
(Если правите `wrangler.toml`, биндинг подхватится при следующем деплое.)

## 2. Переменные окружения и секреты

Cloudflare → **Workers & Pages** → ваш проект → **Settings** → **Variables and Secrets**.

### Обязательные

| Имя | Тип | Значение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | **Secret** | Новый токен от [@BotFather](https://t.me/BotFather) |
| `MASTER_ADMIN_USERNAME` | Text | `plombit` |
| `MASTER_ADMIN_ID` | Text | `1014012851` |
| `TELEGRAM_CHAT_ID` | Text | id чата/канала для уведомлений, напр. `-100…` |

> ⚠️ **Токен бота обязательно перевыпустить.** Прежний токен лежал в исходниках
> в открытом виде — считается скомпрометированным. В @BotFather:
> `/mybots` → выбрать бота → **API Token** → **Revoke current token**.

### Рекомендуемые

| Имя | Тип | Зачем |
|---|---|---|
| `TELEGRAM_WEBHOOK_SECRET` | **Secret** | Telegram будет присылать его в заголовке; без него вебхук принимает любого |
| `SETUP_TOKEN` | **Secret** | Включает служебные роуты `/api/setup-webhook` и `/api/admin/import-legacy`. Пока не задан — они выключены |
| `CRM_APP_URL` | Text | `https://asmalines.by/crm.html` — ссылка на кнопке в боте |
| `ALLOWED_ORIGINS` | Text | `https://asmalines.by,https://www.asmalines.by` — список для CORS |

### Необязательные

| Имя | Зачем |
|---|---|
| `YANDEX_GEOCODER_KEY` | Точный геокодинг по Беларуси. Без него используется бесплатный OpenStreetMap Nominatim |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `LEAD_EMAIL_TO` | Дублирование заявок на e-mail (только локальный сервер; в Worker почта не отправляется) |

**Секрет ≠ текст.** Для токенов выбирайте тип **Secret** (значение нельзя
прочитать в панели повторно), для остальных достаточно Text.

## 3. Разовая миграция заявок из старого хранилища

Прежние заявки лежат в публичном JSON-бине. Перенесите их в D1 один раз.

1. Убедитесь, что заданы `SETUP_TOKEN` и биндинг `DB`, и задеплойте сайт.
2. Выполните:

```bash
curl -X POST "https://asmalines.by/api/admin/import-legacy" \
     -H "x-setup-token: ВАШ_SETUP_TOKEN"
```

Ответ вида `{"ok":true,"imported":4,"skipped":false}` означает, что заявки
перенесены. Повторный вызов безопасен: если в D1 уже есть заявки, импорт
пропускается (`"skipped":true`), дубликатов не будет.

3. **После импорта закройте старый бин.** Он был публичным: любой, кто знал
   ссылку, мог читать телефоны клиентов и перезаписывать базу. Удалите его в
   панели json.extendsclass.com. В коде ссылка на него больше не используется
   как рабочее хранилище — только как источник разового импорта.

## 4. Вебхук Telegram

### 4.1 Зарегистрировать с секретом

```bash
curl -X POST "https://asmalines.by/api/setup-webhook" \
     -H "x-setup-token: ВАШ_SETUP_TOKEN"
```

В ответе должно быть `"ok":true` и `"secretConfigured":true`.
Роут сам передаст Telegram'у ваш `TELEGRAM_WEBHOOK_SECRET`; после этого
поддельные запросы к вебхуку будут отбиваться с кодом 401.

### 4.2 Проверить состояние

```bash
curl "https://asmalines.by/api/telegram-webhook"
```

Ожидаемо: `"configuredBotToken":true`, `"webhookSecretEnforced":true`,
`"storage":"d1"`.

### 4.3 Если секрет ещё не задан

Проверка секрета не enforced, чтобы существующий вебхук не отвалился. Но
**пока секрет не задан, подделать запрос к вебхуку может любой** — задайте
`TELEGRAM_WEBHOOK_SECRET` и выполните п. 4.1.

## 5. Проверка после настройки

```bash
curl https://asmalines.by/api/health
```

Ожидаемый ответ:

```json
{ "ok": true, "status": "healthy", "storage": "d1", "writable": true, "botTokenConfigured": true }
```

- `"storage":"legacy-readonly"` — биндинг `DB` не подхватился, заявки не принимаются.
- `"writable":false` — то же самое.
- `"botTokenConfigured":false` — не задан `TELEGRAM_BOT_TOKEN`.

Затем отправьте тестовую заявку через калькулятор: она должна появиться в
Telegram-чате и в CRM (кнопка «Открыть CRM» в боте).

## 6. Режимы работы

| Состояние | Что работает |
|---|---|
| Нет `DB`, нет секретов | Страницы открываются. API отвечает 500 с понятным текстом. Заявки не принимаются |
| Есть `DB`, нет `TELEGRAM_BOT_TOKEN` | Заявки сохраняются в D1, CRM работает. Уведомления в Telegram не приходят |
| Есть `DB`, нет `TELEGRAM_WEBHOOK_SECRET` | Всё работает, но вебхук не проверяет отправителя |
| Всё настроено | Полный режим |

## 7. Кэширование статики

⚠️ **Самое частое место ошибок.** В `_headers` для `/assets/*` стоит
`max-age=31536000, immutable`: браузер запомнит файл на год. Значит, после
**любой** правки ассета обязательно нужно менять `?v=` в разметке, иначе
вернувшиеся посетители получат старую версию (именно так можно «потерять»
исправление в `site.js` или `calculator.js`).

Для контроля есть автоматическая проверка — она сравнивает хеш содержимого
каждого ассета с записью в `_tools/asset-versions.json`:

```bash
npm run check:assets     # покажет ассеты, изменённые без смены версии
npm run assets:fix       # поднимет ?v= до сегодняшней даты и обновит манифест
```

Проверка входит в `npm run check`, поэтому расхождение не проскочит незаметно.
Новые страницы тоже покрыты: ассеты, подключённые без `?v=`, валидатор отметит
отдельно.

HTML-страницы отдаются с `must-revalidate`, поэтому сами страницы
обновляются сразу.

## 8. Частые проблемы

**«Приём заявок временно недоступен: не настроено хранилище D1»**
Не задан биндинг `DB` или он назван иначе. Проверьте `wrangler.toml` или
раздел D1 database bindings.

**CRM открывается, но пустая, и пишет «Доступ запрещён»**
initData не проходит проверку. Проверьте, что `TELEGRAM_BOT_TOKEN` —
актуальный токен **того же** бота, через которого открывают CRM.

**Бот не отвечает на /start**
Вебхук не зарегистрирован либо указывает на старый адрес. Выполните п. 4.1.

**В консоли браузера ошибки Content-Security-Policy**
Появился новый инлайн-скрипт или обработчик `onclick`. CSP намеренно строгий:
весь JS должен лежать в файлах `assets/*.js`. Быстрая проверка:

```bash
node _tools/prepare-csp.mjs && node _tools/extract-theme-and-csp.mjs
```

**Заявка сохранилась, но уведомление не пришло**
Не задан `TELEGRAM_CHAT_ID` или бот не добавлен в этот чат/канал.

## 9. Локальная разработка

```bash
cp .dev.vars.example .dev.vars   # и заполнить значения
npm install
npm run dev                      # http://localhost:3000
```

`npm run check` прогоняет всё сразу: проверку синтаксиса, контроль версий
ассетов, валидацию разметки, ESLint и тесты (78 проверок, включая сверку
расчёта цены между Worker'ом, сервером и браузером).

| Команда | Что делает |
|---|---|
| `npm run dev` | локальный сервер на `http://localhost:3000` |
| `npm test` | 78 тестов (цена, валидация, безопасность, хранилище, клиент) |
| `npm run lint` | ESLint |
| `npm run check:assets` | ассеты, изменённые без смены `?v=` |
| `npm run assets:fix` | поднять `?v=` и обновить манифест версий |
| `npm run check:html` | целостность разметки, inline-обработчики, битые ссылки |
| `npm run smoke:crm` | сквозная проверка CRM на запущенном сервере |

Сквозная проверка CRM (25 сценариев: авторизация, попытка подмены полей,
подделка тикета, права ролей):

```bash
npm run dev                                              # в отдельном терминале
node _tools/smoke-crm.mjs http://localhost:3000 ВАШ_ТОКЕН БОТА 1014012851
```
