### Ключевые решения, которые стоит помнить

**Биндинг называется `DB`.** Worker читает `env.DB`. Если имя изменить,
хранилище не подхватится и заявки перестанут приниматься — сайт вернётся
в режим только для чтения.

**Работаем на workers.dev.** `asmalines.by` не существует, поэтому canonical,
`og:url`, `og:image`, `twitter:image`, JSON-LD `@id`, sitemap, robots и
`CRM_APP_URL` указывают на рабочих адрес. Когда появится свой домен —
запустите `node _tools/switch-domain.mjs`, предварительно поменяв в нём
константы `OLD_HOST` / `NEW_HOST`.

**CORS не привязан к домену.** По умолчанию разрешается собственный origin
запроса, поэтому переезд не требует правки кода. `ALLOWED_ORIGINS` нужен
только если API начнут вызывать сторонние сайты.

**Секреты лежат в `~/.cf-secrets.txt`** (вне репозитория). Значения
`TELEGRAM_BOT_TOKEN` в файле нет — он задаётся только в Cloudflare.

## Если нужно поднять всё заново

### 1. База данных D1

```bash
npx wrangler d1 create asma-lines          # запомнить database_id
npx wrangler d1 execute asma-lines --remote --file=./schema.sql
```

Затем в `wrangler.toml` подставить `database_id` в блок `[[d1_databases]]`
(имя биндинга — строго `DB`).

### 2. Секреты

Cloudflare → **Workers & Pages** → `asma-lines-site` → **Settings** →
**Variables and Secrets**:

| Имя | Тип | Значение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | **Secret** | токен от [@BotFather](https://t.me/BotFather) |
| `MASTER_ADMIN_USERNAME` | Text | `plombit` |
| `MASTER_ADMIN_ID` | Text | `1014012851` |
| `TELEGRAM_CHAT_ID` | Text | id чата/канала для уведомлений |
| `TELEGRAM_WEBHOOK_SECRET` | **Secret** | см. `~/.cf-secrets.txt` |
| `SETUP_TOKEN` | **Secret** | см. `~/.cf-secrets.txt` |
| `YANDEX_MAPS_API_KEY` | **Secret** | ключ [Кабинета разработчика Яндекс](https://developer.tech.yandex.ru/) (JS API и Геокодер) |
| `CRM_APP_URL` | Text | `https://asma-lines-site.firws.workers.dev/crm.html` |
| `TELEGRAM_BOT_USERNAME` | Text | имя бота в ссылке входа (по умолчанию `asmalinesbot`) |

Добавить ключ Яндекс.Карт в Cloudflare через консоль:
```bash
npx wrangler secret put YANDEX_MAPS_API_KEY
```

`ALLOWED_ORIGINS` — только для сторонних сайтов, для работы самого сайта не нужен.

### 3. Деплой

```bash
npx wrangler deploy
```

### 4. Вебхук

```bash
node _tools/setup-webhook-secret.mjs
```

Скрипт сгенерирует секрет, зарегистрирует вебхук у Telegram **с** секретом,
сохранит значения в Cloudflare и проверит, что подделка отбивается с 401.

### 5. Перенос заявок из старого хранилища

Скрипт сначала показывает план, потом применяет:

```bash
node _tools/import-legacy-to-d1.mjs          # предпросмотр
node _tools/import-legacy-to-d1.mjs --apply  # применить
```

Он же делает резервную копию снапшота в домашний каталог.

## Вход в диспетчерскую

С телефона диспетчерская открывается из бота: личность подтверждает сам
Telegram (подписанный `initData`). На компьютере так работать неудобно —
окно внутри Telegram тесное, без вкладок и привычного масштаба, — поэтому
ПК-версия открывается как обычный сайт и входит по коду:

1. Браузер показывает код (например `482-173`) и QR-код со ссылкой на бота.
2. Диспетчер подтверждает вход в боте кнопкой — там же видно **устройство,
   город и время** входа.
3. Браузер получает сессионную cookie на 30 дней и открывает диспетчерскую.

Команды бота: `/login 482-173` — подтвердить вход по коду, `/logout` —
закрыть все браузерные сессии сотрудника (например, если вход был не его).

Как это защищено:

- код одноразовый, живёт 5 минут, не больше 10 кодов на адрес в час;
- подтвердить код может только аккаунт из списка доступа;
- в базе (таблицы `sessions`, `login_codes`) хранятся только sha256-хеши
  токенов, самих токенов там нет;
- cookie: `HttpOnly; Secure; SameSite=Lax`;
- запросы с cookie принимаются только со своего источника и с заголовком
  `X-Requested-With: asma-crm` — защита от CSRF;
- отзыв доступа в CRM закрывает уже открытые сессии автоматически;
- каждый браузерный вход бот сообщает оператору сообщением.

Роуты: `POST /api/login/start`, `GET /api/login/qr`, `GET /api/login/status`,
`POST /api/logout`. Таблицы создаются автоматически при первом запросе
(`ensureSchema`), вручную применять `schema.sql` не нужно.

Кнопки в боте приходят в вебхук как `callback_query`, поэтому он указан в
`allowed_updates`. Если вебхук регистрировался до этого изменения,
перерегистрируйте его:

```bash
curl -H "x-setup-token: $SETUP_TOKEN" https://asma-lines-site.firws.workers.dev/api/setup-webhook
```

```bash
curl https://asma-lines-site.firws.workers.dev/api/health
```


Затем отправьте тестовую заявку через калькулятор: она должна появиться в
Telegram-чате и в CRM (кнопка «Открыть CRM» в боте).

## Кэширование статики

⚠️ **Самое частое место ошибок.** В `_headers` для `/assets/*` стоит
`max-age=31536000, immutable`: браузер запомнит файл на год. Значит, после
**любой** правки ассета обязательно нужно менять `?v=` в разметке, иначе
вернувшиеся посетители получат старую версию (именно так можно «потерять»
исправление в `site.js` или `calculator.js`).

Для контроля есть автоматическая проверка — она сравнивает хеш содержимого
каждого ассета с записью в `_tools/asset-versions.json`:

```bash
npm run check:assets     # покажет ассеты, изменённые без смены версии
npm run assets:fix       # поднимет ?v= до сегодняшней даты и обновит манифест
```

Проверка входит в `npm run check`, поэтому расхождение не проскочит незаметно.
Новые страницы тоже покрыты: ассеты, подключённые без `?v=`, валидатор отметит
отдельно.

HTML-страницы отдаются с `must-revalidate`, поэтому сами страницы
обновляются сразу.

## Частые проблемы

**«Приём заявок временно недоступен: не настроено хранилище D1»**
Не задан биндинг `DB` или он назван иначе. Проверьте `wrangler.toml` или
раздел D1 database bindings.

**CRM открывается, но пустая, и пишет «Доступ запрещён»**
initData не проходит проверку. Проверьте, что `TELEGRAM_BOT_TOKEN` —
актуальный токен **того же** бота, через которого открывают CRM.

**Бот не отвечает на /start**
Вебхук не зарегистрирован либо указывает на старый адрес. Выполните п. 4.1.

**В консоли браузера ошибки Content-Security-Policy**
Появился новый инлайн-скрипт или обработчик `onclick`. CSP намеренно строгий:
весь JS должен лежать в файлах `assets/*.js`. Быстрая проверка:

```bash
node _tools/prepare-csp.mjs && node _tools/extract-theme-and-csp.mjs
```

**Заявка сохранилась, но уведомление не пришло**
Не задан `TELEGRAM_CHAT_ID` или бот не добавлен в этот чат/канал.
